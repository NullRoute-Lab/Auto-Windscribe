# Auto-Windscribe

رابط ترمینالی لینوکس برای مدیریت و بررسی اتصال با **برنامهٔ رسمی Windscribe**.
این پروژه غیررسمی است و وابستگی یا تأیید رسمی از طرف Windscribe ندارد. برنامه یک VPN مستقل
نیست؛ از همان `/usr/bin/windscribe-cli` نصب‌شده استفاده می‌کند و حساب، تونل و فایروال در اختیار
کلاینت رسمی باقی می‌مانند.

**وضعیت این نسخه:** پیاده‌سازی و آزمون آفلاین انجام شده است. در جلسهٔ توسعه هیچ اتصال واقعی
VPN آزمایش نشده است. عملیات واقعی به‌صورت پیش‌فرض قفل است و به اجازهٔ جداگانه نیاز دارد.
[مرز مجوز آزمون](docs/TEST_AUTHORIZATION.md) را بخوانید.

## نصب روی Bluefin

محیط هدف: لینوکس x86_64، Bluefin بر پایهٔ Fedora 44، GNOME 50 روی Wayland و Windscribe 2.25.8.
به Python 3.12 یا جدیدتر نیاز است. نصب هیچ بستهٔ سیستمی، دسترسی روت یا تغییر در rpm-ostree
نمی‌خواهد. از Windscribe نصب‌شده و حساب واردشدهٔ فعلی استفاده کنید.

```bash
uv tool install --python 3.12 git+https://github.com/NullRoute-Lab/Auto-Windscribe.git
~/.local/bin/auto-windscribe --help
```

اجرای نسخهٔ محلی از مخزن:

```bash
uv sync --python 3.12
uv run auto-windscribe --demo
```

نصب فقط محیط پایتون و فرمان اجرایی را ایجاد می‌کند؛ هیچ اتصال، اسکن یا سرویس پس‌زمینه‌ای را
شروع نمی‌کند. اگر لازم بود، `~/.local/bin` را به PATH شل اضافه کنید.

## شروع و کنترل‌ها

```bash
auto-windscribe
```

رابط ترمینالی وضعیت، مکان‌ها و پورت‌های مجاز را از CLI رسمی می‌خواند. تا وقتی اجازهٔ عملیات
واقعی فعال نشده، اتصال یا اسکن اجرا نمی‌شود. اتصال موجود نیز خودکار قطع نمی‌شود.

برای پیش‌نمایش کاملاً آفلاین:

```bash
auto-windscribe --demo
```

نام‌ها و اعداد حالت demo ساختگی و مشخصاً شبیه‌سازی‌شده‌اند؛ در فضای موقت ذخیره می‌شوند و وارد
تاریخچهٔ واقعی نمی‌شوند. `--offline` فقط کش و تاریخچهٔ قبلی را می‌خواند. `--dry-run` برنامهٔ
عملیات را نمایش می‌دهد و CLI یا آزمون شبکه را اجرا نمی‌کند؛ به کش قبلی یا حالت demo نیاز دارد.

| کلید | کارکرد |
| --- | --- |
| `/` یا `Ctrl+F` | جست‌وجوی تقریبی کشور، شهر و نام سرور |
| کلیدهای جهت و Page Up/Down | حرکت در جدول |
| `Space` | انتخاب چند ترکیب برای اسکن هدفمند |
| `Enter` | تأیید اتصال به ترکیب انتخاب‌شده |
| `R` | اسکن انتخاب‌ها یا نتایج فیلترشده |
| `F` | فیلتر کشور، شهر، نام سرور و سطح دسترسی |
| `P` | اولویت پروتکل، پورت و تنظیمات اسکن |
| `S` | ذخیرهٔ پروفایل برنامه؛ بارگذاری از انتخابگر پروفایل |
| `O` | تغییر ترتیب رتبه‌بندی |
| `D` | تأیید قطع اتصال سیستم |
| `X` | توقف کار برنامه و حفظ وضعیت فعلی VPN |
| `U` | تازه‌سازی فهرست رسمی |
| `?` یا `F1` | راهنما |
| `Esc` | بستن پنجره یا بازگشت به جدول |
| `Q` یا `Ctrl+C` | خروج و حفظ اتصال VPN |

زبانه‌های سرورها، رتبه‌بندی و عیب‌یابی وضعیت آزمایش‌ها را نشان می‌دهند. خط تیره یعنی داده
اندازه‌گیری نشده؛ به‌معنی صفر نیست. رابط فعلاً انگلیسی است؛ ساختار gettext برای ترجمهٔ آینده
در نظر گرفته شده است.

## فرمان‌های خواندنی و برنامه‌ریزی

```bash
auto-windscribe status
auto-windscribe doctor
auto-windscribe locations --search Amsterdam
auto-windscribe locations --countries
auto-windscribe protocols
auto-windscribe scan --profile restrictive --dry-run
auto-windscribe results --sort rtt
auto-windscribe results --history --json
auto-windscribe results --scans
auto-windscribe profiles
```

فرمان doctor هیچ ping یا آزمون HTTPS و اتصال واقعی اجرا نمی‌کند. خروجی خام CLI، نشانی IP عمومی،
رمز و توکن ذخیره نمی‌شود. اگر تازه‌سازی فهرست شکست بخورد، آخرین کش معتبر با برچسب قدیمی نمایش
داده می‌شود؛ فهرست ساختگی جایگزین نمی‌شود. نبودن علامت Pro به‌معنی رایگان بودن سرور نیست.

## استفادهٔ واقعی، فقط پس از اجازهٔ جداگانه

این بخش در جلسهٔ توسعه نباید بدون پاسخ صریح «بله» اجرا شود. پس از اجازه، نمونهٔ
`examples/config.json` را در `~/.config/auto-windscribe/config.json` کپی کنید و مقدار
`live_enabled` را `true` قرار دهید. فرمان‌های واقعی همچنین `--live` می‌خواهند و رابط ترمینالی
تأیید می‌گیرد. متغیر `AUTO_WINDSCRIBE_OFFLINE=1` بر اجازهٔ عملیات واقعی مقدم است.

```bash
# عملیات واقعی: ممکن است اینترنت موقتاً قطع شود.
auto-windscribe scan --profile restrictive --max-tests 8 --live
auto-windscribe connect "Stroopwafel" --protocol stealth --port 443 --live
auto-windscribe disconnect --live
```

نام سرور و پورت را از فهرست فعلی خودتان انتخاب کنید؛ مثال بالا تضمین در دسترس بودن نیست.
اسکن باید در حالت قطع‌شده شروع شود. برای جایگزینی اتصال موجود، ابتدا خودتان Disconnect را
تأیید کنید یا در CLI از `connect --interrupt --live` استفاده کنید. برنامه هرگز فایروال را
غیرفعال نمی‌کند.

فعال‌کردن هم‌زمان `live_enabled` و `auto_scan` در تنظیمات، رضایت به شروع اسکن پیش‌فرض هنگام
اجرای برنامه است؛ فقط وقتی VPN قطع باشد. برای بررسی دستی انتخاب‌ها، `auto_scan` را خاموش
نگه دارید. نصب هیچ‌کدام را فعال نمی‌کند.

پروفایل restrictive اول Stealth، WStunnel و TCP را امتحان می‌کند؛ این ترتیب تضمین عبور از
محدودیت‌های شبکه نیست. پورت‌ها از CLI کشف می‌شوند. سقف پیش‌فرض ۱۲ تلاش است و دانلود اختیاری
۱ مگابایتی به‌صورت پیش‌فرض خاموش است. آزمون آپلود وجود ندارد.

حالت first-success اتصال موفق را نگه می‌دارد. حالت rank فقط بین گزینه‌ها اتصال خودش را قطع
می‌کند و وضعیت نهایی را حفظ می‌کند. خروج و توقف هیچ disconnect نمی‌فرستند؛ درخواستی که قبلاً
ارسال شده ممکن است بعد از خروج کامل شود. ادامهٔ اسکن متوقف‌شده با
`scan --resume SCAN_ID --live` یا دکمهٔ Resume انجام می‌شود و سقف تلاش‌های قبلی حفظ می‌شود.

## دقت و محدودیت‌ها

موفقیت به وضعیت متصل، پروتکل و پورت منطبق و HTTPS از دستگاه تونل تأییدشده نیاز دارد. بسته‌شدن
ICMP به‌تنهایی تونل را ناموفق نمی‌کند. CLI ممکن است فقط شهر را گزارش کند؛ بنابراین نام سرور
به‌عنوان **مقصد درخواست‌شده** ذخیره می‌شود، نه مقصدی که همیشه مستقل تأیید شده است. هنگام اسکن
با کنترل‌های GUI کار نکنید. این برنامه ابزار تأیید ناشناس‌بودن یا نبود نشت DNS/IPv6 نیست.

تنظیمات AmneziaWG، SNI، DNS، مسیریابی، MTU، split tunneling و TLS padding از طریق روش‌های داخلی
دستکاری نمی‌شوند. doctor نام پریست‌های موجود را نشان می‌دهد؛ پریست فعال از این CLI معلوم نیست.

رتبه‌بندی از تاریخچهٔ موفقیت، اتلاف بسته، RTT، jitter، زمان اتصال و تازگی نتیجه استفاده می‌کند.
برای جداسازی نتایج شبکه‌ها یا تنظیمات متفاوت، برچسب‌های `network_label` و `settings_label` را
در پروفایل تغییر دهید. SSID یا IP عمومی برای شناسایی خودکار جمع‌آوری نمی‌شود.

## ذخیره‌سازی، به‌روزرسانی و حذف

- تنظیمات: `$XDG_CONFIG_HOME/auto-windscribe/`، معمولاً `~/.config/auto-windscribe/`
- تاریخچه و صف: `$XDG_DATA_HOME/auto-windscribe/`، معمولاً `~/.local/share/auto-windscribe/`
- کش فهرست: `$XDG_CACHE_HOME/auto-windscribe/`، معمولاً `~/.cache/auto-windscribe/`

```bash
uv tool upgrade auto-windscribe
uv tool uninstall auto-windscribe
```

حذف برنامه، Windscribe یا اتصال فعلی آن را متوقف نمی‌کند. تاریخچه حفظ می‌شود؛ برای پاک‌کردن
داده‌ها فقط پوشه‌های XDG متعلق به auto-windscribe را پس از بررسی مسیر حذف کنید.

## آزمون آفلاین

```bash
uv sync --frozen
uv run ruff check src tests
uv run ruff format --check src tests
uv run mypy
AUTO_WINDSCRIBE_OFFLINE=1 uv run pytest
```

آزمون‌ها اتصال شبکه و ساخت فرایند واقعی را مسدود می‌کنند و از آداپتورهای شبیه‌سازی‌شده استفاده
می‌کنند. مجوز استاندارد MIT و [قدردانی از پروژه‌های مرجع](THIRD_PARTY_NOTICES.md) در مخزن آمده است.
