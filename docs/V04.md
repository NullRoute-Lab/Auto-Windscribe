# v0.4 settlement and exhaustive execution

## Evidence and correction

Read-only application history confirmed that the latest saved scan (5) paused after one
`connection_timeout`, phase establishment, with Connecting observed. The preceding scan had the
same shape. The v0.3 recovery code used `range(max_recoveries)` for native state polling: two
Connecting responses consumed the entire default allowance, each followed by a two-second sleep.
It could return RECOVERY_FAILED despite unused time in its 25-second overall deadline. This is a
proven application defect. The later read-only Disconnected status supports late settlement;
the precise native transition time and cause of negotiation failure were not recorded then.
The screenshot and final report are observations at different times, not proof of a continuous
firewall state. No real probe or tunnel operation was run to reproduce this during v0.4 development.

## Settlement state machine

WAITING_FOR_NATIVE → NATIVE_SETTLING → BASELINE_CHECKING → RECOVERED → CONTINUING_SCAN.
Unexpected owned-state mismatches become EXTERNAL_CONNECTION_DETECTED; unresolved IPC dispatch
becomes UNSAFE_STATE. Deadline or baseline retry exhaustion becomes RECOVERY_EXHAUSTED.

Native observations no longer consume the baseline retry allowance. They use a monotonic native
settlement deadline (default 60s), polling from 0.5s up to 3s with 1.5× backoff. State or firewall
transitions reset backoff and the quiet interval. A continuously Disconnected state must remain
stable for recovery_delay (default 2s), then pass baseline checks and a final native/firewall
comparison. The overall recovery deadline (90s) and session budget also bound this work. Short
status failures invalidate quiet-state evidence. Cancellation retains the native connection.

Every distinct observed native/firewall transition is timestamped; at most 256 are retained.
No address, interface, route gateway or credential is recorded. The timeline is an observation
sequence, not a subscription to every native event: changes between polls may be invisible.
The Diagnostics tab displays settlement progress without labeling ordinary waiting a failure.

A timed-out observed negotiation can settle to Disconnected and continue after baseline checks.
A dispatch timeout or crashed in-flight dispatch is different: no request ID/terminal acknowledgment
is available, so quiet Disconnected alone does not resolve it. It remains paused for inspection.
A late connected but unowned tunnel is preserved. Known owned matched tunnels can be disconnected
through the official interface; no other network control or recovery connection is issued.

## Durable queue and manifest

The selected full eligible matrix is stored before execution; the 1,000-row TUI display cap has
no effect on it. Profiles still filter only officially discovered supported ports/locations.
Session attempt/time budgets leave remaining rows intact, retaining the original scan ID.
`results --manifest ID --json` reports total, completed, remaining, tested, verified, failed,
unknown, cancelled, skipped and sessions. Tested counts distinct candidates with recorded outcomes,
including unknown/cancelled observations, not guaranteed completed handshakes. Skipped is zero:
there is no automatic skip policy. Catalog changes pause with the original queue preserved.
Unavailable entries must become available again or the user explicitly create a differently
filtered job; the controller does not silently discard them.

Results are committed BEFORE recovery. A separate recovery record includes `settlement_resolved`;
UNKNOWN is never rewritten into FAILED to advance. Completion checkpoints follow verified recovery.
Cancellation during settlement preserves the original outcome. A durable in-flight reservation
protects a hard crash before an outcome is committed. Resume examines pending prior observations
before redispatch, resolving them safely or pausing. Ambiguous dispatch/cancellation requires user
inspection; it cannot be declared safe automatically with the desktop IPC surface.

Each confirmed session has a durable identifier, start/end and attempt count. An unclosed session
record after a crash remains historical evidence; the next session resumes the same job. Schema v3
migrates v1/v2 and adds sessions/reservations. Back up app data before downgrading; older releases
refuse the newer schema. The complete profile is the persisted scope manifest; no regenerated
matrix substitutes for the existing queue. Retry budgets remain bounded per candidate/session.

Exhaustive defaults to continued ranking after successes. Use `--no-continue-after-success` for
first success, or `--continue-after-success` explicitly. Turbo defaults to first verified success.
Resumes use the saved job profile; changing CLI filters on a resume does not rewrite its scope.
The Continue scan button and `scan --resume ID` reuse the job. Stop/Pause retain all checkpoints.
If connected from the previous session, explicitly disconnect before continuation; existing
connections are never silently replaced. Session and whole-job progress are shown separately.
ETA appears after three observations and includes measured attempt/recovery time and interval;
it excludes unknowable future outages and can change dramatically. Thousands of handshakes are
not promised to finish in minutes. Earlier-session durations are retained in results/recovery
records; the displayed forecast uses the current session's pace.

## Firewall and GUI limitations

A healthy baseline requires DNS and both HTTPS samples; failed ICMP alone is allowed. A firewall
label is not proof of packet blocking. On/Always On with failed baseline stays unsafe, with policy
untouched. A firewall transition invalidates settlement evidence. No VPN-only bypass mode is
shipped: supported behavior has not been verified under intentional kill-switch blocking. The
scanner never claims ordinary internet restoration from a native Disconnected label alone.

Manual strategy and GUI handler were re-reviewed in upstream source. Two internal manual failures
emit the nonautomatic notification that opens the Auto proposal. Explicit protocol requests use
shared desktop IPC; `-n` changes CLI waiting behavior, not backend isolation. Accepting Auto changes
preferences and restarts connection. No supported suppression flag was found. Closing a window
may only hide it; exiting the desktop engine is not a demonstrated supported headless replacement.
No clicks, setting writes or helper termination are performed. See HEADLESS_MIGRATION.md for the
recommended future architecture and permission-gated migration plan.

## Commands

```bash
auto-windscribe scan --profile exhaustive --max-tests 100 --session-budget 3600 --settlement-timeout 60 --recovery-timeout 90
auto-windscribe results --scans
auto-windscribe results --manifest 5 --offline --json
auto-windscribe scan --resume 5
auto-windscribe recovery-status --offline --json
```

Native endpoint TCP preflight remains unavailable without trusted address mapping; no guessed
addresses or parallel system tunnels were added. All implementation tests use injected fakes.
