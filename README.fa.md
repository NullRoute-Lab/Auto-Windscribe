# Auto-Windscribe ۰٫۵

مدیر و تحلیل‌گر اتصال VPN در ترمینال لینوکس، با استفاده از **کلاینت رسمی Windscribe**.
این پروژه غیررسمی است و موتور VPN جداگانه‌ای ندارد. حساب، تونل سراسری سیستم، فایروال و
تنظیمات دسکتاپ همچنان در اختیار برنامهٔ رسمی هستند.

[English](README.md) · [معماری](docs/ARCHITECTURE.md) · [قابلیت‌ها](docs/CAPABILITIES.md)
· [بررسی Turbo](docs/TURBO.md) · [مجوز آزمون توسعه](docs/TEST_AUTHORIZATION.md)

## نصب و شروع

محیط هدف: Bluefin / Fedora 44، لینوکس x86_64، Python 3.12 یا جدیدتر و Windscribe 2.25.8
نصب‌شده و واردشده به حساب. نیازی به روت، نصب RPM، تغییر سیستم اتمیک یا سرویس پس‌زمینه نیست.

```bash
uv tool install --python 3.12 git+https://github.com/NullRoute-Lab/Auto-Windscribe.git
auto-windscribe
```

اگر اتصال قطع باشد، پیشنهاد Turbo نمایش داده می‌شود. **یک بار Enter را فشار دهید** تا اسکن
محدودشده آغاز شود. همان تأیید برای تمام تلاش‌های آن جلسه کافی است. نیازی به ویرایش JSON،
متغیر محیطی یا فعال‌کردن قفل دائمی نیست. اگر از قبل متصل باشید، برنامه اتصال شما را جایگزین
نمی‌کند؛ ابتدا با اقدام صریح خودتان قطع کنید. با **Q** خارج شوید؛ VPN سیستم متصل می‌ماند.

برنامه برای استفادهٔ واقعی و آگاهانهٔ کاربر آماده است؛ اما عامل توسعه در این جلسه فقط مجاز
به آزمون آفلاین است. اجازهٔ آزمون واقعی قبلی مصرف شده و برای آزمون تازه باید دوباره اجازه بگیرد.
موفقیت اتصال واقعی در شبکهٔ هدف هنوز تأیید نشده است.

## کشف سه‌مرحله‌ای

۱. فهرست مکان‌ها و پورت‌های پشتیبانی‌شده از CLI رسمی گرفته می‌شود؛ تمام ترکیب‌های انتخابی
WireGuard، UDP، TCP، Stealth و WStunnel ساخته می‌شوند. IKEv2 در ماتریس نیست.

۲. موتور پیش‌آزمون ناهمگام، هم‌زمانی محدود، کش DNS، اتصال TCP بدون ارسال محتوای برنامه‌ای،
مهلت، بودجهٔ تعداد آزمون، محدودیت نرخ و لغو را پیاده می‌کند. مقدار پیش‌فرض هم‌زمانی ۱۶ و
مهلت TCP برابر ۱٫۵ ثانیه است. فقط موجودی معتبر رسمی می‌تواند نشانی واقعی فراهم کند.

**محدودیت فعلی:** CLI نسخهٔ 2.25.8 نشانی گره‌ها و نگاشت پروتکل به `ip/ip2/ip3` را صادر
نمی‌کند. دادهٔ PortMap رسمی احراز هویت می‌خواهد. برنامه نه اطلاعات ورود را می‌خواند و نه
از نام مستعار سرور، آدرس حدس می‌زند. بنابراین پیش‌آزمون بومی فعلاً «نامشخص / نشانی در
دسترس نیست» گزارش می‌دهد و هیچ DNS یا TCP واقعی اجرا نمی‌کند. موتور با موجودی و شبکهٔ
شبیه‌سازی‌شده آزموده شده؛ مرحلهٔ بعد از انتخاب تطبیقی و تلاش‌های بومی ترتیبی استفاده می‌کند.

۳. تاریخچه، تنوع کشور و پروتکل و شواهد موجود، ترتیب تلاش‌ها را تعیین می‌کنند. در هر لحظه
فقط یک تلاش واقعی Windscribe فعال است. موفقیت به وضعیت صحیح CLI، مسیر تونل و HTTPS
مقید به رابط تونل نیاز دارد. TCP موفق، پینگ VPN یا موفقیت تونل محسوب نمی‌شود. سکوت UDP
نشانهٔ بازبودن پورت نیست. پیش‌آزمون TLS به‌دلیل ناشناخته‌بودن SNI مؤثر فعال نیست.

| پروفایل | تلاش بومی در هر جلسه | مهلت برقراری | بودجهٔ زمان | رفتار |
| --- | ---: | ---: | ---: | --- |
| Turbo پیش‌فرض | ۱۲ | ۲۰ ثانیه | ۳۰۰ ثانیه | توقف با اولین موفقیت تأییدشده |
| Balanced | ۳۶ | ۳۰ ثانیه | ۱۲۰۰ ثانیه | تنوع بیشتر و اندازه‌گیری کیفیت |
| Exhaustive | ۱۰۰ | ۳۵ ثانیه | ۳۶۰۰ ثانیه | نگهداری کل ماتریس و ادامه در جلسات محدود |

شکست یک گزینه اسکن را از ابتدا شروع نمی‌کند. نتیجه‌ها و صف باقی‌مانده ذخیره می‌شوند.
وضعیت نامعلوم یا تغییر اتصال توسط برنامه‌ای دیگر باعث توقف برای بررسی می‌شود؛ قطع خودکار
در چنین حالتی انجام نمی‌شود. درخواست بومی ارسال‌شده ممکن است بعد از توقف برنامه تکمیل شود.
ادامهٔ اسکن به حالت قطع‌شده و تأیید یک جلسهٔ تازه نیاز دارد.

## کلیدها و نمایش

| کلید | کار |
| --- | --- |
| `/` یا Ctrl+F | جست‌وجوی تقریبی کشور، منطقه، شهر و نام مستعار |
| F | فیلتر مکان و نوع سرور |
| P | انتخاب پروتکل، پورت و بودجه؛ پورت خالی یعنی همهٔ پورت‌های پشتیبانی‌شده |
| S | ذخیرهٔ پروفایل و برچسب شرایط شبکه/تنظیمات |
| Space | علامت‌گذاری ترکیب دقیق مکان/پروتکل/پورت |
| Enter | تأیید پیشنهاد آغاز یا اتصال گزینهٔ انتخابی |
| R | اسکن دوبارهٔ گزینه‌های فیلترشده |
| Resume | ادامهٔ صف ذخیره‌شده با بودجهٔ تازه |
| X | توقف/مکث، بدون قطع VPN |
| D | قطع اتصال با تأیید |
| O | تغییر مرتب‌سازی؛ منوی مرتب‌سازی گزینه‌های بیشتری دارد |
| U | تازه‌سازی فهرست رسمی |
| A | روشن/خاموش‌کردن پیشنهاد اسکن هنگام اجرا؛ تأیید همچنان لازم است |
| `?` یا F1 | راهنما |
| Esc | بستن پنجره / بازگشت به جدول |
| Q یا Ctrl+C | خروج و حفظ اتصال سیستم |

ستون‌های پیش‌آزمون و تأخیر TCP از پینگ، جیتر و اتلاف بستهٔ تونل جدا هستند. جدول برترین‌ها
نرخ موفقیت تاریخی و زمان برقراری را نشان می‌دهد. پس از سه تلاش کامل، تخمین زمان جلسه از
زمان‌های مشاهده‌شده محاسبه می‌شود؛ این تخمین وعدهٔ یافتن اتصال موفق نیست.

## فرمان‌ها

```bash
auto-windscribe status
auto-windscribe doctor
auto-windscribe locations --search Amsterdam
auto-windscribe protocols
auto-windscribe scan --profile turbo
auto-windscribe scan --profile balanced --max-tests 8
auto-windscribe scan --profile exhaustive --protocol stealth
auto-windscribe scan --resume 1
auto-windscribe connect Stroopwafel --protocol stealth --port 443
auto-windscribe disconnect
auto-windscribe results --sort rtt
auto-windscribe results --scans
```

نام سرور نمونه است؛ ابتدا موجودبودن فعلی آن را در فهرست بررسی کنید. فرمان‌های تعاملی یک بار
تأیید می‌گیرند. برای اسکریپت از رضایت صریح `--live` استفاده کنید:

```bash
auto-windscribe scan --profile turbo --max-tests 3 --preflight-budget 16 --session-budget 120 --live
```

هیچ فرمانی برای اسکن، اتصال موجود را بی‌صدا جایگزین نمی‌کند. جایگزینی با فرمان connect علاوه
بر تأیید به `--interrupt` نیاز دارد. رابط رسمی Windscribe را هنگام اسکن تغییر ندهید؛ وضعیت
CLI ممکن است فقط شهر را نشان دهد و دو اتصال به همان شهر/پروتکل/پورت قابل تفکیک نباشند.

## استفاده و آزمون آفلاین

```bash
auto-windscribe --demo
auto-windscribe --offline
auto-windscribe scan --profile turbo --dry-run --json
uv sync --frozen
uv run pytest -m 'not live' --cov=auto_windscribe
uv run ruff check src tests benchmarks
uv run mypy
uv run python -m benchmarks.preflight
uv build
```

حالت‌های offline و dry-run هیچ فرمان بومی یا آزمون شبکه اجرا نمی‌کنند و فایل‌های دائمی برنامه
را تغییر نمی‌دهند. برنامه‌ریزی آفلاین به کش واقعی قبلی نیاز دارد؛ فهرست ساختگی جایگزین نمی‌شود.
Demo فقط داده و آداپتر مصنوعی دارد. آزمون‌ها اجرای زیرفرایند واقعی، DNS و اتصال سوکت را مسدود می‌کنند.

اندازه‌گیری مصنوعی: میانهٔ سه اجرا برای ۳۲ نقطه با تأخیر شبیه‌سازی‌شدهٔ ۱۰۰ میلی‌ثانیه،
**۳٫۲۰۶۸۵۱ ثانیه ترتیبی در برابر ۰٫۴۱۴۸۴۷ ثانیه هم‌زمان؛ ۷٫۷۳ برابر**. محدودیت ۱۰۰ آغاز
در ثانیه، اوج هم‌زمانی مشاهده‌شده را به ۱۰ رساند. این نتیجه دربارهٔ زمان‌بندی موتور است،
نه بهبود واقعی سرعت VPN. [دادهٔ اندازه‌گیری](docs/benchmark-v0.2.json).

## تنظیمات، به‌روزرسانی و حذف

تنظیمات AmneziaWG، Anti-Censorship، SNI، مسیر جایگزین، DNS، فایروال، split tunneling،
IPv6، MTU و TLS padding در برنامهٔ رسمی باقی می‌مانند. پس از تغییر دستی آن‌ها، برچسب
`settings_label` پروفایل را عوض کنید تا نتیجه‌ها با شرایط متفاوت مخلوط نشوند.
هیچ رمز، توکن یا کلید خصوصی ذخیره نمی‌شود. داده‌ها در زیرپوشهٔ `auto-windscribe` مسیرهای
استاندارد XDG قرار می‌گیرند. فیلد قدیمی `live_enabled` نادیده گرفته می‌شود.

```bash
uv tool upgrade auto-windscribe
uv tool uninstall auto-windscribe
```

برای نصب قبلی از wheel محلی، [راهنمای نصب](docs/INSTALL.md) روش انتقال به منبع Git را توضیح
می‌دهد. حذف برنامه، Windscribe و تاریخچه را حذف نمی‌کند. مجوز MIT و
[قدردانی از منابع](THIRD_PARTY_NOTICES.md) در مخزن موجود است.

## نسخهٔ ۰٫۳: بررسی شبکه و بازیابی

پیش از هر تلاش واقعی، DNS، پینگ دو بسته‌ای گوگل، HTTPS گوگل و یک مقصد مستقل بررسی می‌شود.
شکست پینگ به‌تنهایی مانع ادامه نیست. پس از شکست، برنامه وضعیت بومی را مشاهده می‌کند، فقط
تونل متعلق به همان اسکن را در صورت نیاز با فرمان رسمی قطع می‌کند و سلامت شبکه را دوباره
می‌سنجد. با بازیابی تأییدشده، صف ادامه می‌یابد؛ درخواست نامعلوم یا تعارض رابط گرافیکی باعث
مکث امن می‌شود. فایروال، DNS و مسیرهای سیستم تغییر نمی‌کنند.

پنجرهٔ Switch to Auto متعلق به برنامهٔ رسمی است و قابل سرکوب از این کنترل‌گر نیست.
پذیرفتن آن می‌تواند حالت مشترک را تغییر دهد و اتصال تازه‌ای آغاز کند. هنگام اسکن رابط رسمی
را تغییر ندهید. چرخهٔ اتصال/قطع برای بازیابی پیاده نشده چون تضمین حفظ تنظیمات و پایان درخواست
قبلی با رابط پشتیبانی‌شده ممکن نیست. تعداد بازیابی، تعداد بررسی مجدد سلامت است، نه اتصال تازه.

```bash
auto-windscribe network-check --dry-run
auto-windscribe network-check
auto-windscribe scan --profile turbo --auto-recover --max-recoveries 2
auto-windscribe recovery-status
```

فرمان بررسی واقعی تأیید می‌خواهد؛ doctor و recovery-status فقط خواندنی هستند. گزینه‌های
بازیابی در پنجرهٔ P قرار دارند. آزمون توسعه فقط با آداپتر مصنوعی انجام شده؛ کارایی بازیابی
واقعی هنوز تأیید نشده است. [جزئیات و محدودیت‌ها](docs/RECOVERY.md).

## نسخهٔ ۰٫۴: انتظار برای پایان درخواست بومی و اسکن کامل

محدودیت اشتباه دو مشاهده حذف شد. اکنون وضعیت بومی تا مهلت مستقل، با فاصلهٔ افزایشی بررسی
می‌شود. پیش‌فرض مهلت نشست بومی ۶۰ ثانیه و کل بازیابی ۹۰ ثانیه است؛ بودجهٔ جلسه همچنان
حد نهایی است. تغییر فایروال یا وضعیت، زمان پایداری را از نو آغاز می‌کند. پس از قطع پایدار،
سلامت پایه و وضعیت نهایی دوباره بررسی می‌شوند. نتیجهٔ UNKNOWN تغییر نمی‌کند؛ تأیید پایان
عملیات در رکورد جدا ذخیره می‌شود و فقط پس از بازیابی امن، صف ادامه می‌یابد.

کل ماتریس ذخیره می‌شود؛ سقف نمایش ۱۰۰۰ ردیف اثری بر صف ندارد. دکمهٔ Continue scan و
فرمان resume همان شناسه را ادامه می‌دهند. وضعیت نامعلوم IPC یا قطع فرایند هنگام ارسال
باعث مکث محافظه‌کارانه می‌شود، نه ارسال اتصال هم‌زمان. شمارندهٔ کل کار و جلسه جدا هستند
و تخمین زمان، سربار بازیابی مشاهده‌شده را هم در نظر می‌گیرد.

```bash
auto-windscribe scan --profile exhaustive --settlement-timeout 60 --recovery-timeout 90
auto-windscribe results --manifest 5 --offline --json
auto-windscribe scan --resume 5
```

پنجرهٔ رسمی Switch to Auto قابل سرکوب از این کنترل‌گر نیست. بستهٔ رسمی CLI-only برای
بررسی جداگانه توصیه شده، ولی هیچ بسته یا تنظیم سیستمی تغییر نکرده است.
[جزئیات](docs/V04.md) و [برنامهٔ مهاجرت برگشت‌پذیر](docs/HEADLESS_MIGRATION.md).


## نسخهٔ ۰٫۵: بازیابی اختیاری رابط رسمی و جلوگیری از تکرار

بازیابی با راه‌اندازی دوبارهٔ رابط Windscribe به‌صورت پیش‌فرض خاموش است. در تنظیمات P یا با
`--gui-restart-recovery` آن را فعال کنید. ابتدا Auto-connect را در برنامهٔ رسمی خاموش کنید.
پس از خطای مستند بومی، ابتدا انتظار برای پایان تلاش و بررسی شبکه انجام می‌شود. فقط در صورت
احراز وضعیت Disconnected، ورود حساب، Firewall Off و نبود درخواست معلق، فرایند دقیق رابط رسمی
با SIGTERM متوقف و دوباره اجرا می‌شود. هیچ helper یا سرویس شبکه‌ای متوقف نمی‌شود.

روشن یا نامعلوم بودن فایروال، اتصال فعال یا وضعیت نامعلوم مانع راه‌اندازی دوباره است؛ خروج
خود برنامهٔ رسمی ممکن است بر سیاست فایروال اثر بگذارد. بنابراین خطای اخیر با Firewall On با
راه‌اندازی مجدد کورکورانه رفع نمی‌شود. وجود پنجرهٔ Switch to Auto از CLI قابل اثبات نیست؛
هیچ کلیک خودکار یا تغییر تنظیمات رسمی انجام نمی‌شود. کلید G درخواست بازیابی دستی را می‌دهد.

نتیجهٔ UNKNOWN تغییر نمی‌کند. پس از تأیید پایان امن تلاش، یک وضعیت deferred جداگانه ذخیره
می‌شود و ادامهٔ اسکن ترکیب دیگری را انتخاب می‌کند. شناسهٔ اسکن، تاریخچه، صف کامل و بودجهٔ
جلسه حفظ می‌شوند. Ctrl+R یا فرمان زیر فقط موارد deferred امن را صریحاً دوباره در صف می‌گذارد؛
اسکن را شروع نمی‌کند:

```bash
auto-windscribe recover-gui --dry-run
auto-windscribe scan --profile exhaustive --gui-restart-recovery
auto-windscribe scan --resume 6 --gui-restart-recovery
auto-windscribe results --manifest 6 --offline --json
auto-windscribe retry-deferred 6
```

در صورت شکست بازیابی، صف حفظ و اسکن متوقف می‌شود. لغو عملیات ممکن است رابط رسمی را بسته
باقی بگذارد؛ برنامه آن را پنهانی دوباره اجرا نمی‌کند. فرمان status رسمی می‌تواند رابط بسته را
باز کند؛ بنابراین حالت terminal-only برای بستهٔ دسکتاپ ارائه نشده است. راهنمای دقیق در
[GUI_RECOVERY.md](docs/GUI_RECOVERY.md) و طرح مهاجرت جداگانه در
[HEADLESS_MIGRATION.md](docs/HEADLESS_MIGRATION.md) موجود است. هیچ آزمایش واقعی اتصال، شبکه یا
بستن رابط رسمی در مرحلهٔ توسعه مجاز نیست.
